# Как агент делает страницу

Репозиторий превращает ответ на сложный вопрос в одну HTML-страницу.
Агент пишет только черновик в Markdown. Вёрстку делает сборщик `scripts/am.mjs`.

## 1. Главное правило

Не писать HTML, CSS и SVG руками. Писать только черновик `.md`.
Сборщик сам делает сетку, цвета, тёмную тему, диаграммы и координаты схем.
Рукописный HTML в черновике разрешён только тогда, когда готового компонента нет.

## 2. Когда делать страницу

Страница нужна, если верно хотя бы одно:

- в ответе три и больше связанных понятий, и читателю надо видеть связи;
- есть процесс, порядок шагов, развилка или роли нескольких участников;
- есть сравнение по трём и более признакам;
- есть иерархия или развитие во времени;
- есть вывод, который человек будет пересказывать другому.

Страница не нужна для болтовни, для одной цифры и когда человек просит простой текст.
Сомневаетесь — отвечайте текстом.

## 3. Порядок работы

1. Разбить ответ на 3–8 панелей. Одна панель — один вопрос.
2. Первая панель или строка `Lead` даёт главный вывод. Следующие панели дают доказательства.
3. Выбрать компонент по форме данных (раздел 5).
4. Записать черновик файлом `draft.md`.
5. Собрать страницу и прочитать вывод сборщика:

```bash
node scripts/am.mjs render draft.md -o out/page.html --no-open
```

6. Если в выводе `✓ путь` и `STE 0 warnings`, страница готова. Строка `✗ L<номер>`
означает, что страница не собрана: исправьте строки из списка и запустите сборку снова.

Правка одной панели готовой страницы:

```bash
node scripts/am.mjs patch out/page.html --panel "Название панели" panel.md
```

## 4. Формат черновика

```markdown
---
template: sheet
title: Заголовок страницы
subtitle: Одна строка — суть
source: Автостат, октябрь 2026
---

Lead: одно или два предложения с главным выводом.

## A Название панели
Обычный Markdown: абзацы, списки, таблицы, цитаты.

## B Вторая панель
Текст.
```

Поля шапки:

| Поле | Значение |
|---|---|
| `title` | Заголовок страницы, обязателен |
| `subtitle` | Одна строка под заголовком |
| `template` | `sheet` — обзор на один экран (по умолчанию), `doc` — чтение по шагам |
| `theme` | `auto` (по умолчанию), `blueprint`, `shadcn`, `paper` |
| `cols` | Сколько панелей в ряду, по умолчанию 3 |
| `lang` | Язык страницы, например `ru`. Определяется по тексту автоматически |
| любое другое поле | Показывается в шапке как справка, например `source: …` |

Буква перед названием панели (`## B Название`) задаёт её идентификатор. Можно не писать.

## 5. Компонент по форме данных

| Форма данных | Компонент | Минимальный синтаксис |
|---|---|---|
| Что с чем связано, схема, развилка | `flow` | `A -> B: подпись`, `A --> C` пунктир, `{вопрос?}` решение |
| Сущности и их поля | `er` | сущность в начале строки, поля с отступом |
| Обмен сообщениями во времени | `sequence` | `A -> B: запрос`, `B --> A: ответ` |
| Иерархия, состав | `tree` | отступ задаёт уровень |
| Этапы во времени | `timeline` | `время \| заголовок \| описание` |
| Значение против предела | `limits` | `метка \| 13 / 20 \| единица` |
| Числа для сравнения | `chart bar` / `chart line` / `chart pie` | `метка \| 12`, серии в первой строке |
| Построчный разбор фразы | `annot` | `[фрагмент]{заметка}` |
| Титульный блок, реквизиты | `kv` | `ключ: значение` |
| Вывод, риск | `callout ok\|warn\|err\|info Заголовок` | тело обычным Markdown |
| Выбор читателя | `ask` | строка вопроса, затем `* вариант \| заметка` |
| Сравнение по признакам | таблица Markdown | в колонке статуса `ok` / `no` / `warn` |
| Код из проекта | блок кода с `src=` и `lines=` | ```` ```ts src=path/lines.ts lines=18-30 ```` |
| Изменения в коде | блок `diff` | строки начинаются с `+`, `-`, пробела или `@@` |

Примеры синтаксиса:

````markdown
## Процесс

```flow
Аукцион -> Выкуп: ставка
Выкуп -> Порт: фрахт
Порт -> Клиент: выдача
```

## Цены по месяцам

```chart line
январь | 100
февраль | 105
март | 112
```

```callout warn Риск
Цена курса не фиксируется в договоре.
```
````

Полная справка: `node scripts/am.mjs help format`, справка по компоненту:
`node scripts/am.mjs help flow`.

## 6. Как писать текст

- Сразу вывод. Без вступления «в этой статье мы рассмотрим».
- Одно предложение — одна мысль. Длинные фразы делить на две.
- Факт называется один раз. Если он есть в таблице, в тексте его не повторять.
- Каждая цифра имеет источник и дату. Оценку помечать словом «оценка».
- Данные не выдумывать. Нет чисел — не рисовать график.
- Демонстрационные числа помечать словом «демо» в описании панели или графика.
- Список давать полностью. Не заканчивать его словом «и т. д.».
- Непроверенный факт называть непроверенным и указывать, как его проверить.
- Личные данные людей в страницу не попадать: адреса, телефоны, суммы по конкретным людям.

Сборщик проверяет часть этих правил и печатает предупреждения `STE`.
Предупреждение не мешает сборке, но текст лучше поправить.
Режим `style: strict` в шапке черновика запрещает сборку с нарушениями.

## 7. Язык

Язык черновика — язык вопроса. По умолчанию русский.
Поле `lang` в шапке задаёт язык страницы и подписи кнопок.

## 8. Проверка перед выдачей

- В выводе сборщика есть `✓` и путь к файлу.
- Строк `✗` нет. Предупреждений `STE` нет или они объяснены.
- Таблица и график сходятся с источником: сумма колонки равна итогу источника.
- Личных данных в тексте нет.
- Страница открывается без интернета.
